## 规范化与判定规则

1. **排版规范化**：Unicode NFKC（全角/半角、`Ⅰ/Ⅱ/Ⅲ`、全角括号/字母）、去空白、括号统一为半角、连字符 `-–—−` 删除、枚举顿号 `、` 删除、拉丁字母小写、希腊字母统一。
2. **原名列优先**：2017/2019/2020 的 `原名（2022通用名更新前）` 建立 `旧名|剂型 → 规范名|剂型`，confidence=1.0。原名列非空行只有 22/77/135 行，**空原名列不等于已规范**。
3. **规范化精确匹配**：规范化后药名与剂型完全一致（仅排版差异）→ 自动映射，confidence 0.92–0.95。
4. **剂型标签仅差“剂”字**（`胶囊↔胶囊剂`、`颗粒↔颗粒剂` 等）且同名一对一 → confidence 0.9 自动映射；`口服常释剂型→片剂/胶囊剂`、`膏→软膏`、`散剂→空`、`丸剂→滴丸`、`胶囊→软胶囊` 等**不**自动合并。
5. **复合剂型**（药名内嵌 `（胶囊、颗粒）`、`片（胶囊）`，或剂型列写成 `口服常释剂型口服液体剂颗粒剂`）→ 一律进 `nhi_name_splits.csv`，不自动合并。
6. **模糊候选**：同剂型（或剂型同义）`difflib` 相似度 ≥ 0.80 进 candidates，< 0.80 进 unmatched，均不自动合并。
7. **禁止交叉**：不跨剂型、不合并盐型/复方/不同给药途径；一个旧 key 最多一个规范 key。

### 2) 系统性问题

- **剂型词表不统一**：2021 年起 `口服常释剂型` 拆成 `片剂/胶囊剂`，`膏/散剂` 大量变空。同名不同剂型的 248 条在 candidates，未自动合并；map 里 351 条“胶囊↔胶囊剂”也属于剂型标签层面，如口径更严可一并回退。
- **原名列覆盖极低**：2017/2019/2020 分别 22/77/135 行；空原名不能推断为已规范。
- **词典独有旧 key**：359 个 key 不在当前 CSV（旧版 `未分类`/旧名），重建词典后会自然消失；map 中已覆盖其中 130 个有原名列证据的旧名。
- **限制值冲突**：归并后同一规范 key 同一年出现多个 `医保限制` 的有 0 个 key。接入时应取并集并标记冲突，不要后写覆盖。
- **模糊候选的盐型/规格风险**：相似度高不代表同一药（`丙酸氯倍他索` vs `氯倍他索`、`聚苯乙烯磺酸钙` vs `聚苯乙烯磺酸`），候选表必须人工过。

## 校验

- `nhi_name_map.json` 为合法 JSON（UTF-8），key 唯一；同一旧 key 不会映射到多个规范 key。
- 所有 `canonical_key` 均能在原始数据中找到：PASS。
- 4 条已知必含映射：全部 PASS。
- 除剂型标签“剂”字差异外，跨剂型自动映射：0 条。
- 链式归并：1 条（`本维莫德|乳膏剂 → 本维莫德乳膏|乳膏`）。
- 三个 CSV 之间、以及与 map 之间没有重复 old_key（已校验）。

## 建议主代码接入方式（只写建议，不改代码）

1. `build_dict.py` 读取 CSV 后，用 `nhi_name_map.json` 把 `(名称, 剂型)` 改写为 `canonical_name|canonical_key 的剂型段`；`restriction_timeline` 取并集，同一年冲突时保留列表或标记 `conflict`，不要静默覆盖。
2. `_match_nhi` 先按原 key 精确匹配；失败再按名称查 map 的旧 key/aliases；最后才用规范化名称。`nhi_name_candidates.csv` / `nhi_name_splits.csv` / `nhi_name_unmatched.csv` **不要**参与自动匹配。
3. 剂型词表单独做一层 `form_alias`（`胶囊→胶囊剂`、`口服常释剂型→片剂/胶囊剂`），与名称映射解耦；本任务出于“不跨剂型”约束未自动合并的那部分应在这里处理。
4. 重建词典后用本 README 对账：map 条数、规范 key 数、`6259 → 5843`。
